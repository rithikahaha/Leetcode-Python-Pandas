# 574. Winning Candidate
LeetCode: https://leetcode.com/problems/winning-candidate/ · Medium

## Problem
Return the name of the candidate who received the most votes. The test data guarantees exactly one winner.

**Candidate**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| name | varchar | |

**Vote**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key, auto-increment |
| candidateId | int | foreign key to `Candidate.id` |

**Example**
```
Candidate: (1, A), (2, B), (3, C), (4, D), (5, E)
Vote: (1, 2), (2, 4), (3, 3), (4, 2), (5, 5)

Output: name = B
```
Candidate 2 (B) got two votes, in rows 1 and 4. Everyone else got one.

## Solution
```python
import pandas as pd

def winning_candidate(candidate: pd.DataFrame, vote: pd.DataFrame) -> pd.DataFrame:
    winner_id = vote['candidateId'].value_counts().idxmax()
    return candidate.loc[candidate['id'] == winner_id, ['name']]
```

1. `value_counts()` tallies how many times each `candidateId` appears in `Vote`. For the example that's `2 → 2` and `4, 3, 5 → 1` each, sorted from most to fewest.
2. `.idxmax()` returns the label of the biggest count, which here is the candidate id itself, `2`. If two candidates tied it would return only the first one, but the problem rules that out.
3. `candidate['id'] == winner_id` picks out that candidate's row, and `['name']` returns just the name column as a DataFrame, which is the shape LeetCode expects. That gives B.

There's no merge because only the winner's name is needed. Counting first and looking up one row afterwards is simpler than attaching a name to every vote.
