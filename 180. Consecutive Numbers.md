# 180. Consecutive Numbers
LeetCode: https://leetcode.com/problems/consecutive-numbers/ · Medium

## Problem
Find every number that appears at least three times in a row in `Logs`.

**Logs**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key, auto-increment, defines row order |
| num | varchar | |

**Example**
```
Logs: (1,1), (2,1), (3,1), (4,2), (5,1), (6,2), (7,2)

Output: ConsecutiveNums = 1
```
Rows 1-3 all hold `1`, three in a row, so `1` qualifies. No other value repeats three times consecutively.

## Solution
```python
import pandas as pd

def consecutive_numbers(logs: pd.DataFrame) -> pd.DataFrame:
    logs = logs.sort_values('id')
    prev1 = logs['num'].shift(1)
    prev2 = logs['num'].shift(2)
    result = logs.loc[(logs['num'] == prev1) & (logs['num'] == prev2), 'num'].unique()
    return pd.DataFrame({'ConsecutiveNums': result})
```

No SQL-style function wrapper is needed here, and this problem never needed one in SQL either, that requirement was specific to 177, where N had to be passed in at call time. This one is a plain fixed query, so it stays a plain function.

1. `sort_values('id')` guarantees row order matches the actual log sequence before doing any row-to-row comparison.
2. `shift(1)` and `shift(2)` pull each row's value from one and two rows earlier, the same idea as SQL's `LAG(num, 1)`/`LAG(num, 2)`, giving every row a view of itself plus its two predecessors without a self-merge.
3. At the row for `id=3`, `num=1`, `prev1=1` (row 2), `prev2=1` (row 1); all three match, so `1` qualifies.
4. At `id=4`, `num=2` but `prev1=1`, so that row fails the filter; the two `2`s at rows 6-7 never reach three in a row either.
5. `.unique()` handles runs longer than three, where several consecutive rows would all pass the filter for the same value, so it should only be reported once.

**Alternative that scales to "at least N in a row" without adding a `shift()` column per N:** tag each row with a run id that increments every time the value changes, then keep values whose run is at least 3 rows long.
```python
def consecutive_numbers(logs: pd.DataFrame) -> pd.DataFrame:
    logs = logs.sort_values('id')
    run_id = (logs['num'] != logs['num'].shift()).cumsum()
    run_length = logs.groupby(run_id)['num'].transform('size')
    result = logs.loc[run_length >= 3, 'num'].unique()
    return pd.DataFrame({'ConsecutiveNums': result})
```
`logs['num'] != logs['num'].shift()` is `True` only where a value differs from the one before it, marking the start of a new run. `.cumsum()` turns those start markers into a running count that stays flat within a run and increases by one every time a new run begins, so every row in the same run ends up sharing the same `run_id`. `groupby(run_id)['num'].transform('size')` then attaches each run's total length back onto every row in it, and filtering `run_length >= 3` keeps only runs long enough to qualify. Bumping the threshold to "at least N" anywhere is then just changing that one number, no extra `shift()` calls needed.
