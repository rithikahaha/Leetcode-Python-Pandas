# 570. Managers with at Least 5 Direct Reports
LeetCode: https://leetcode.com/problems/managers-with-at-least-5-direct-reports/ · Medium

## Problem
Find managers who have five or more people reporting directly to them. Return just their names, any order.

**Employee**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| name | varchar | |
| department | varchar | |
| managerId | int | references Employee.id, null if no manager |

**Example**
```
Employee: (101, John, A, null), (102, Dan, A, 101), (103, James, A, 101), (104, Amy, A, 101), (105, Anne, A, 101), (106, Ron, B, 101)
Output: name = John
```
Five employees (Dan, James, Amy, Anne, Ron) all list John as their manager, meeting the "at least 5" threshold.

## Solution
```python
import pandas as pd

def find_managers(employee: pd.DataFrame) -> pd.DataFrame:
    counts = employee.groupby('managerId').size()
    managers = counts[counts >= 5].index
    return employee[employee['id'].isin(managers)][['name']]
```

1. `groupby('managerId').size()` counts how many rows share each `managerId`, which is the number of direct reports per manager. In the example, `101` shows up 5 times. Rows with a null `managerId` (John himself) are skipped by `groupby`, so they don't get counted as a group of their own.
2. `counts[counts >= 5].index` keeps only the manager ids with 5 or more reports, leaving `[101]`.
3. `employee['id'].isin(managers)` turns those ids back into people, since `managerId` is just a number and the problem wants names. It keeps the row whose own `id` is 101, which is John.
4. `[['name']]` returns just the name column, as a DataFrame.

The SQL version needs a self join because a manager's name lives in a different row than the reports pointing at them. Here the counting and the lookup are two separate steps, so no merge is needed.
